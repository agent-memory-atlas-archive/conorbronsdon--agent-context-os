# Context OS v1.0.0

Context OS 1.0 defines a compatibility promise for reviewed, Git-backed handoffs.
Claude Code, Codex, OpenClaw, OpenCode, Hermes Agent and Cursor CLI are the six
first-class lifecycle adapters. Cursor IDE and Devin remain experimental.

## Stable interfaces

The [compatibility contract](https://github.com/conorbronsdon/agent-context-os/blob/v1.0.0/docs/compatibility-contract.md) covers lifecycle
commands, tracked workspace configuration, runtime descriptors, bundle locks,
component ownership, proposals and receipts. Changes within 1.x preserve the
supported interfaces; durable format changes require versioned migration.

Start reads context. Proposals show changes and an exact digest. Apply rechecks
sources and targets and records a receipt. That digest binds bytes; it does not
authenticate a human approver or provide an upstream agent permission boundary.

## Onboarding and upgrades

The canonical template fixes the 0.15 runtime-registration failure caused by
requiring development evidence excluded from release archives. Setup also
normalizes Windows CRLF answers. Initialize an independent Git repository after
verifying the archive, select agents, and follow the
[first reviewed handoff](https://github.com/conorbronsdon/agent-context-os/blob/v1.0.0/docs/first-handoff.md).

For an existing legacy YAML clone, use its installed release's reviewed
`workspace propose-migration` and `apply` before upgrading. Schema-v1 workspaces
first migrate with their verified installed bundle to schema 2 and the
`full-template` profile, then upgrade with both verified current and candidate
bundles. Selecting a smaller profile is a separate reviewed update. Preserve
customized managed files and resolve conflicts explicitly; seed and extensible
user files remain user-owned. See [workspace configuration](https://github.com/conorbronsdon/agent-context-os/blob/v1.0.0/docs/workspace-configuration.md).

Release qualification runs published 0.14/0.15 migrations, personalized-file
conflict refusal, exact rollback after multiple file publications, live-process
lock exclusion, process-exit journal recovery and post-commit doctor failure
controls on Linux and Windows. It also checks fresh template setup and initialized
start from the same candidate. These are synthetic tests, separate from native
adapter evidence and human onboarding. The release workflow must pass before
publication; source version 1.0.0 alone does not establish a published release.

## Support boundaries

Adapter claims remain bounded by the versions and platforms in their descriptors
and guides. CLI support does not promote IDE, ACP, bot or cloud surfaces. Cursor
IDE approval and implicit skill-read controls remain unqualified. Hooks and
native memory do not replace the shared proposal and receipt boundary.

Download all five attached assets from the immutable release. Begin with
`agent-context-os-template-v1.0.0.OFFLINE-VERIFY.md`; the attached template tar is
the canonical workspace. GitHub's generated source archives are different assets.
